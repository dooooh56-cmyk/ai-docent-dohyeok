# AI 도슨트 개발 계획서

- 작성일: 2026-10-30
- 최종 시연: 2026-12-01
- 중간 시연(스마트폰): 2026-11-04 (수)
- 시연 장소: 국립중앙박물관 서화관 조선 회화실
- LLM: Google Gemini API

이 문서는 ArtBridge(`../ArtBridge_프로젝트_계획서.md`)와 별개인 AI 도슨트 프로젝트의 개발 계획이다. 미확인 사항은 "확인 필요"로 표기하고, 확인되면 근거와 날짜를 함께 갱신한다.

## 1. 목표

렌즈(디스플레이) 없는 스마트 글라스—1인칭 동영상 카메라, 마이크, 이어폰—를 착용한 외국인 관람객에게 **개인화된 대화형 도슨트**를 제공한다. 기존 오디오 가이드처럼 정해진 해설을 재생하지 않고, 관람객이 보고 있는 작품을 인식해 관람객의 배경과 질문에 맞춰 대화한다.

핵심 가치는 **조선 회화와 비교할 만한 외국 회화**를 관람객 프로필에 맞춰 골라 소개하는 것이다. 익숙한 작품을 기준점으로 삼아 조선 회화의 구도·주제·기법·사회적 맥락을 이해하도록 돕는다.

### 시연 시나리오

1. 관람객이 글라스(11/4까지는 스마트폰)를 착용하고 세션을 시작한다.
2. 도슨트가 영어로 짧게 인사하고 프로필 질문 2~3개를 한다. 예: 출신 국가, 익숙한 미술(인상주의, 우키요에 등), 원하는 설명 길이.
3. 관람객이 그림 앞에 서면 카메라 프레임으로 작품을 인식하고 짧게 소개한다.
4. 관람객이 자유롭게 질문하면 작품 근거 자료를 바탕으로 답한다.
5. "고향에서 보셨을 ○○와 비교해 보면…"처럼 프로필에 맞는 외국 회화와 비교하며 유사점과 차이점을 설명한다.
6. 다음 작품으로 이동하면 이미 들은 내용과 관심사를 반영해 설명 깊이를 조절한다.

### 12/1 성공 기준 (초안, 1주차 측정 후 수치 확정)

- 회화실 대상 작품 10~15점 인식
- 작품당 검증된 비교 회화 1~3점
- 영어 음성 대화의 응답 지연 목표: 스파이크 측정 후 확정 (확인 필요)
- 시연 질문 세트에서 콘텐츠 DB와 어긋나는 사실 진술 0건

## 3. 시스템 구조

```text
[글라스 / 스마트폰: 카메라 · 마이크 · 이어폰]
        │  오디오(PCM) + 프레임(JPEG), WebSocket/HTTPS
        ▼
[Python 백엔드 (FastAPI)]
  ├─ 세션 관리: 프로필, 본 작품, 들은 비교
  ├─ 작품 인식: 프레임 → artwork_id 또는 unknown
  ├─ 콘텐츠 DB 조회: 작품 정보, 비교쌍, 출처
  └─ Gemini 호출: Live API 또는 요청-응답 (4장에서 결정)
        │
        ▼
     음성 응답 → 이어폰
```

- **클라이언트 v0 (11/4)**: 스마트폰 브라우저 웹앱. `getUserMedia`로 후면 카메라와 마이크를 사용하고 이어폰으로 출력한다. 브라우저 권한 때문에 HTTPS가 필요하다.
- **글라스 단계**: 상용 글라스를 연결한 스마트폰 앱이나 제조사 SDK를 거쳐 같은 백엔드 프로토콜로 전송한다. 대상 제품과 SDK 가용성은 확인 필요.
- **자체 글라스 트랙**: 병행 개발 중인 자체 글라스도 같은 프로토콜(오디오 PCM, JPEG 프레임, 제어 메시지)을 따르도록 인터페이스 문서만 공유한다.
- Gemini API 키는 백엔드 환경 변수에만 둔다. 클라이언트가 Live API에 직접 연결하면 단기 토큰 사용을 검토한다.

## 4. Gemini 연동 방식 비교

1주차 스파이크에서 두 방식을 같은 작품 2~3점과 같은 질문 세트로 비교해 결정한다.

| 항목 | A. Live API (양방향 오디오·영상 스트리밍) | B. 요청-응답 (STT → 프레임 + 질문 → Gemini → TTS) |
| --- | --- | --- |
| 대화 자연스러움 | 실시간 음성, 끼어들기 가능 | 턴 단위 |
| 응답 지연 | 짧음 | STT·생성·TTS가 합산되어 김 |
| 근거 통제 | 시스템 지시와 function calling으로 DB 조회 | 매 요청에 근거를 직접 넣기 쉬움 |
| 구현·디버깅 | 세션 수명, 재연결, 오디오 포맷 처리 필요 | 단순함 |
| 비용 | 연결 시간과 프레임 빈도에 따라 증가 | 호출 단위 |

- **결정 기준**: 실측 응답 지연(p50/p90), 작품 인식 정확도, 근거 이탈 빈도, 남은 일정 대비 구현 난이도.
- **가설**: 대화는 A(Live API)와 function calling(`get_artwork`, `get_comparisons`, `update_profile`)으로 구성한다. 안정성이 부족하면 B로 전환한다.
- 사용 모델명, SDK(`google-genai`) 버전, 오디오·영상 입력 사양은 스파이크 시점의 공식 문서로 확인해 기록한다. 추정값은 기재하지 않는다.

## 5. 작품 인식

| 방식 | 내용 | 장단점 |
| --- | --- | --- |
| 1안: Gemini 분류 | 프레임과 회화실 작품 후보 목록(ID·제목)을 보내 하나를 고르거나 `unknown` 반환 | 구현이 빠름. 호출 비용과 지연이 발생 |
| 2안: 임베딩 매칭 | 사전 촬영한 기준 이미지 임베딩과 코사인 유사도로 매칭 | 빠르고 저렴함. 기준 이미지 촬영 필요 |

- 회화실에서 직접 찍은 사진으로 두 방식의 정확도를 비교한다. 조명, 유리 반사, 비스듬한 각도, 다른 관람객 가림을 포함한다.
- 2안은 ArtBridge의 임베딩·검색 방식을 참고할 수 있지만, 코드를 공유하거나 결합하지 않고 `docent/` 안에 따로 둔다.
- 확신이 낮으면 추측하지 않고 "Which painting are you looking at?"처럼 다시 묻는다.
- 프레임은 인식에 필요할 때만 샘플링하고 저장하지 않는다.

## 6. 콘텐츠 DB (`docent/data/`, 예정)

### `artworks.csv`

`artwork_id`, 원문 제목, 영문 제목, 작가, 시대, 재질·형식, 소장번호, 전시 위치, 공식 작품 페이지 URL, 확인일, 핵심 설명, 설명 출처.

### `comparisons.csv`

`joseon_artwork_id`, 외국 작품명·작가·소장처·공식 URL, 비교 관점(구도/주제/기법/사회적 맥락), 대상 프로필 태그(국가·익숙한 사조), 유사점, 차이점, 근거 출처, 검증 상태.

### 비교 후보 (모두 미검증 가설)

| 조선 회화 | 비교 후보 | 비교 관점 |
| --- | --- | --- |
| 정선 진경산수 | 세잔 「생트빅투아르 산」 연작, 호쿠사이 「후가쿠 36경」 | 실제 장소를 화가의 시선으로 재구성 |
| 김홍도 풍속화 | 브뤼헐 농민 그림 | 일상 노동과 놀이의 기록 |
| 신윤복 풍속화 | 우키요에 미인화 | 도시 문화와 여성 인물 표현 |
| 책가도 | 유럽 트롱프뢰유, '호기심의 방' 그림 | 사물 배치와 지식·취향의 과시 |
| 윤두서 「자화상」 | 뒤러 「자화상」(1500) | 정면 자화상과 화가의 자의식 |

- 조선 회화실은 작품을 정기적으로 교체하므로 시연 시점의 실제 전시 목록을 현장과 박물관 공식 사이트에서 확인한 뒤 DB를 확정한다. 위 작품의 전시 여부는 확인 필요.
- 비교는 영향 관계나 계보로 단정하지 않는다. "비교해 볼 만한 관점"으로 제시하고 차이점도 함께 설명한다.
- 이미지를 앱에 보여주지 않는 음성 중심 시연을 기본으로 한다. 이미지를 표시하거나 임베딩에 쓰면 공공누리·오픈액세스 등 작품별 이용 조건, URL, 확인일, 크레딧을 기록한다.

## 7. 개인화 대화 설계

### 프로필

| 필드 | 예시 | 용도 |
| --- | --- | --- |
| 출신 국가·지역 | France, Japan, USA | 비교 작품 선택 |
| 익숙한 미술 | Impressionism, ukiyo-e, Renaissance | 비교 작품 선택 |
| 설명 깊이 | short / detailed | 응답 길이 |
| 관심 주제 | 일상생활, 풍경, 기법 | 설명 관점 |

### 비교 작품 선택 규칙

1. 현재 작품의 검증된 비교쌍만 후보로 사용한다.
2. 프로필 태그가 일치하는 후보를 우선한다.
3. 같은 세션에서 이미 소개한 비교 작품과 비교 관점은 뒤로 미룬다.
4. 일치하는 후보가 없으면 가장 널리 알려진 비교쌍을 사용하고, 관람객에게 익숙한 작품을 묻는다.

### 응답 원칙

- 작품 사실은 콘텐츠 DB 근거만 사용한다. 근거가 없으면 확인되지 않았다고 말한다.
- 음성 응답은 2~4문장으로 짧게 하고, 다음 질문이나 관찰 포인트를 제안한다.
- 비교는 유사점과 차이점을 함께 말한다.
- 세션 메모리(본 작품, 들은 비교, 반응)는 세션 종료 시 폐기한다. 음성과 프레임은 기본적으로 저장하지 않는다.
