# ArtBridge

한국과 해외 불교 조각의 유사 작품 추천 시스템

개인 프로젝트 실행 계획서 및 모듈 명세서  |  2026년 10월 27일

한국 불교 조각 한 점을 입력하면 중국·일본·인도/간다라의 작품 가운데 시각적·메타데이터상 가까운 사례를 찾아 비교할 수 있게 한다. 첫 6주는 권리 확인이 끝난 소규모 데이터와 재현 가능한 이미지 검색을 완성하는 데 집중한다. AI 도슨트 프로젝트의 작품 식별·출처·이미지 권리 관리 경험은 기술 배경으로 참고하지만, ArtBridge는 별도 저장소와 일정으로 운영하는 개인 프로젝트다.

| 계획 요약 | 결정 |
| --- | --- |
| 문제 | 한국 불교 조각과 해외 불교 조각 사이의 시각적 닮음과 차이를 탐색하기 어렵다. |
| 사용 흐름 | 한국 작품 선택/이미지 입력 → DINOv2 또는 CLIP 임베딩 → 코사인 유사도 검색 → 해외 후보 Top-5와 메타데이터 비교 |
| MVP 데이터 | 20점 파일럿(권역별 5점) 후 최대 120점(한국 30, 중국 30, 일본 30, 인도·간다라 30)으로 확장 |
| 6주 후 산출물 | 라이선스 기록이 있는 데이터 카탈로그, 재현 가능한 임베딩·검색 스크립트, 간단한 로컬 데모, 모듈별 기능 명세, 검색 평가 결과와 다음 단계 제안 |

## 1. 목표와 문제 정의

목표는 한국 불교 조각을 기준점으로 삼아 동아시아와 남아시아의 작품을 함께 탐색하는 개인 연구·시연용 추천 시스템을 만드는 것이다. 추천은 역사적 영향이나 계보를 판정하지 않는다. 이미지 임베딩은 화면상 형상 유사도를 찾는 도구이며, 시대·재질·도상·자세·지역 메타데이터는 별도 비교 근거로 제시한다.

| 항목 | 정의 |
| --- | --- |
| 사용자 문제 | 작품 정보를 국가·박물관별 사이트에서 따로 찾아야 하며, 형태·자세·재료의 비교 대상을 한 번에 보기 어렵다. |
| MVP 목표 | 한국 작품 1점을 고르면 중국·일본·인도/간다라 집합에서 시각적으로 가까운 해외 작품 5점을 보여주고, 각 항목에 유사도 점수와 비교 가능한 메타데이터 및 출처를 표시한다. |
| 성공 판정 | 권리·출처 필드가 채워진 작품 20점 이상; 검색 가능한 해외 작품 15점 이상; 평가 쿼리 10개 이상; Top-5 결과를 사람 평가하고 모델/설정/데이터 버전을 기록; 로컬 데모에서 재현 가능. |
| 권장 성공 기준 | 평가 쿼리 10개에서 사람이 관련 있다고 판단한 결과 비율(Precision@5)의 평균 0.50 이상을 탐색 기준으로 삼는다. 이는 초기 목표치이며, 라벨 수가 작으므로 통계적 성능 보장으로 해석하지 않는다. |

## 2. 사용자 시나리오와 추천 정의

1. 사용자가 카탈로그에서 한국 작품을 고르거나, 허가된 한국 작품 이미지 파일을 입력한다. MVP에서는 먼저 카탈로그 선택 방식으로 동작하고, 업로드 입력은 같은 파이프라인을 쓰는 보조 경로로 둔다.

1. 시스템이 작품 이미지 임베딩을 불러와 중국·일본·인도/간다라 작품 집합과 코사인 유사도를 계산한다.

1. 점수 상위 해외 작품 5점을 반환한다. 사용자는 국가/권역 필터를 적용해 특정 권역 안의 Top-5도 볼 수 있다.

1. 결과에는 작품명, 권역, 연대/시대, 재질, 도상/자세(확인된 경우), 소장 박물관, 이미지 권리 상태, 출처 링크를 표시한다. “형태가 닮았다”와 “시대·재료가 같다”를 구분한다.

1. 사용자는 결과가 관련 있는지 간단히 표시할 수 있고, 이 라벨은 모델 개발 집합과 분리된 평가 파일에 보관한다.

추천 순위의 MVP 정의: 이미지 임베딩 코사인 유사도 단독으로 Top-5를 산출한다. 메타데이터는 설명용 비교 항목과 필터로 먼저 제공한다. 검증 전 임의의 혼합 가중치를 점수에 더하지 않는다. 후속 실험에서 이미지 유사도와 메타데이터 기반 순위를 독립 비교한 뒤 결합 여부를 정한다.

## 3. MVP 범위와 제외 범위

| 포함 | 제외(후속 후보) |
| --- | --- |
| 한국 작품을 질의로 선택하고 해외 작품 Top-5 검색 | 해외 작품을 질의로 한 양방향 검색 |
| DINOv2와 CLIP 임베딩 비교, L2 정규화 후 코사인 유사도 | 학습 데이터로 모델 파인튜닝, 다국어 텍스트-이미지 검색 최적화 |
| 20점 파일럿에서 시작해 120점 목표로 확장 | 전 세계 불교미술 전체를 대표한다고 주장하는 대규모 수집 |
| 작품별 메타데이터 비교, 필터, 출처·권리 표시 | 계보·전파 경로·영향 관계에 대한 자동 학술 판정 |
| 배치 임베딩 생성과 로컬 웹/노트북 데모 | 공개 배포, 계정·클라우드 인프라, 상용 서비스 |
| 정적 검색 결과 평가 및 사람의 관련성 판단 | 근거 문헌을 검색·인용해 설명하는 RAG. 6주 MVP에서는 미구현 |

## 4. 공식 데이터 수집처와 이미지 권리 확인

우선 후보는 작품 상세 페이지에서 소장품 식별자·설명·이미지 권리 정보를 함께 확인할 수 있는 공식 박물관 컬렉션이다. 수집 우선순위는 “작품 적합성 → 이미지 이용 조건 명확성 → 이미지 품질 → 메타데이터 충실도”로 둔다.

| 권역 | 공식 수집처 / 용도 | 권리·수집 메모 |
| --- | --- | --- |
| 한국 | 국립중앙박물관 소장품 검색 및 e뮤지엄 전국박물관 소장품 검색. 불상·보살상 등 키워드, 시대, 재질, 소장기관으로 후보를 찾는다. e뮤지엄은 통합 검색과 Open API 진입점을 제공한다. | e뮤지엄은 공공누리 원칙을 안내하지만, 개별 레코드·이미지의 별도 표시와 이용 조건을 확인한다. 작품 페이지 URL, 소장번호, 라이선스 표기와 조회일을 기록한다. |
| 중국 | Smithsonian National Museum of Asian Art / Freer Gallery 컬렉션. 중국 불교 조각 후보와 공개 이미지 확인에 적합. | 개별 작품 페이지의 Restrictions and Rights가 CC0인 이미지부터 채택한다. 기관 전체의 모든 이미지가 CC0라고 가정하지 않는다. |
| 일본 | Tokyo National Museum 컬렉션, ColBase, e-Museum. 시대·재료·소장번호가 있는 일본 조각 및 간다라 관련 비교 후보 조사. | TNM의 무료 이용 조건은 특정 디지털 아카이브 자료와 비상업 목적 등에 한정된다. TNM 웹사이트 이미지 전부에 적용되지 않으며 조건 미충족 이미지는 신청/사용 제외한다. |
| 인도/간다라 | Tokyo National Museum 및 Smithsonian NMAA의 간다라 출토/지역 작품 레코드를 우선 사용하고, 필요 시 The Met Open Access에서 작품을 보충한다. | 기관·작품별 권리 상태를 확인한다. Met은 OA 아이콘이 붙은 이미지에만 해당 Open Access 조건을 적용한다. 이미지 권리와 메타데이터 권리를 각각 기록한다. |

### 4.1 이미지 라이선스 수집 절차

1. 후보 페이지에서 작품 단위로 권리 문구·아이콘·다운로드 가능 여부를 확인한다. 공공 도메인/CC0, 공공누리 유형, 비상업 제한, 허가 필요, 불명확 중 하나로 분류한다.

1. MVP 로컬 실험은 명시적으로 사용 가능한 이미지와 조건을 지킬 수 있는 자료만 내려받는다. 라이선스가 불명확하거나 “웹에 보인다”는 사실만 확인된 이미지는 저장·임베딩하지 않는다.

1. 크롭·리사이즈 등 전처리가 필요한 경우 원본 파일과 파생 파일을 분리하고 처리 이력을 남긴다. 기관이 변형 표시를 요구하면 결과 화면/크레딧에 반영한다.

1. 비공개/로컬 프로젝트라도 접근 제한이나 비상업 조건을 임의로 넓혀 해석하지 않는다. 공개 데모, 논문·발표, 상업화 전에는 해당 용도별로 다시 확인한다.

권리 판단은 프로젝트 차원의 실무 기록이며 법률 자문이 아니다. 라이선스 레코드의 원문 URL과 확인일을 보존해 이후 다시 검토할 수 있게 한다.

## 5. 데이터 수집 계획

| 단계 | 규모와 배분 | 선정 규칙 | 완료 조건 |
| --- | --- | --- | --- |
| 파일럿 | 20점: 한국 5, 중국 5, 일본 5, 인도/간다라 5 | 공식 소장품 페이지 및 권리 확인 가능 이미지; 정면/전신 등 비교 가능한 사진 우선; 불상·보살상·부조 등 유형을 기록 | 20 레코드 모두 작품 ID·출처·권리 상태 포함; 이미지 파일 해시·파일 경로 연결; 사용불가 건은 이유 기록 |
| 확장 | 목표 120점: 한국 30, 중국 30, 일본 30, 인도/간다라 30 | 동일한 권역별 할당을 목표로 하되 권리·자료 부족 시 실제 확보 수와 편차를 명시; 미확인 정보를 억지로 채우지 않음 | 권리 확인된 120점 목표 도달 또는 6주 종료 시 확보 수로 동결; 권역별 분포와 결측률 보고 |
| 평가 큐레이션 | 20점 이상 중 한국 질의 10점 이상; 별도 관련성 라벨 | 질의 작품과 동일 객체, 같은 촬영 이미지, 다른 각도/복제 레코드가 후보군에 중복 포함되지 않도록 검토 | 쿼리 목록·후보 목록·사람 판정 기준 버전 고정 |

표본 다양성은 시대, 권역, 재료, 불상/보살상/기타 유형을 균형 있게 포함하도록 기록하되, 각 범주의 역사적 대표성을 주장하지 않는다. 후보가 모자라는 권역은 임의 복제하지 말고 불균형을 데이터 설명과 평가 결과에 드러낸다.

## 6. 메타데이터 및 파일 스키마

CSV 또는 JSONL을 원본 카탈로그로 유지하고, 이미지와 임베딩은 artwork_id로 연결한다. 원문 표기를 보존하는 필드와 정규화 값을 구분해 번역·시대 구분을 덮어쓰지 않는다.

| 필드 | 형식 / 필수 | 설명 |
| --- | --- | --- |
| artwork_id | 문자열 / 필수 | 프로젝트 내부 고유 ID. 예: KR_NMK_0001. 소장기관 식별자와 별개. |
| title_original, title_ko, title_en | 문자열 / 원문명 필수 | 기관 원문명과 프로젝트 번역명을 분리. 확인되지 않은 번역은 비워 둔다. |
| region, country_origin | 열거/문자열 / 필수 | Korea, China, Japan, India_Gandhara 등 프로젝트 분류와 기관 표기를 분리. |
| period_original, period_normalized, date_text | 문자열 / 가능하면 | 기관 원문 연대, 비교용 표준 구간, 실제 설명 문구를 따로 기록. |
| object_type, iconography, pose | 문자열/태그 / 선택 | 불상·보살상·부조, 도상, 자세. 근거가 있는 값만 기입. |
| material_original, material_normalized | 문자열 / 선택 | 기관 표현 및 정규화 재질(예: schist/편암)을 함께 보관. |
| museum, accession_number | 문자열 / 권장 | 소장기관명과 소장번호. |
| object_page_url, metadata_source, metadata_accessed_at | URL/문자열/날짜 / 필수 | 개별 레코드 출처, 정보 출처 유형, 수집 확인 날짜. |
| image_path, image_source_url, image_credit | 경로/URL/문자열 / 이미지 사용 시 필수 | 로컬 이미지 및 원본 이미지 링크, 요구되는 크레딧. |
| image_license, license_url, rights_status, rights_checked_at | 문자열/분류/날짜 / 이미지 사용 시 필수 | 정확한 라이선스/문구 링크, 허용·제한·허가필요·불명확 상태, 확인 날짜. |
| image_sha256, image_view_id | 문자열 / 이미지 사용 시 권장 | 중복 탐지용 해시와 객체의 촬영 시점/각도별 이미지 ID. |
| split_group_id, split | 문자열 / 평가 사용 시 필수 | 동일 객체·복제 레코드를 같은 그룹으로 묶고 train/dev/test 또는 query/gallery 지정. |
| notes, uncertainty | 문자열 / 선택 | 표기 차이, 정보 충돌, 불확실성, 수동 보정 기록. |

```text
│   ├── catalog.py                    # 카탈로그 검증과 권리 게이트
│   ├── fetch_images.py               # 승인 이미지 재다운로드·해시 확인
│   ├── embed.py                      # 이미지 임베딩 생성·저장
│   ├── search.py                     # 해외 작품 Top-k 검색
│   ├── compare_metadata.py           # 메타데이터 병렬 비교
│   └── evaluate.py                   # 지표 산출과 누수 점검

```


### 6.2 시스템 파이프라인

```text
한국 작품 선택 또는 질의 이미지 입력
  → 입력 검증 및 이미지 전처리
  → DINOv2 또는 CLIP 이미지 임베딩
  → L2 정규화된 해외 작품 임베딩과 코사인 유사도 계산
  → 중국·일본·인도/간다라 후보에서 전체 Top-5 반환 (선택 시 권역 필터 적용)
  → 작품 메타데이터·출처·권리 정보를 결과 카드에 병렬 표시
  → 고정 평가 질의와 사람 관련성 판단으로 품질 측정
```

카탈로그 작품 임베딩은 데이터/모델 버전별로 한 번 생성해 파일로 저장하고 검색 때 재사용한다. 120점 규모에서는 NumPy 배열을 이용한 완전탐색 코사인 유사도로 충분하므로 FAISS 같은 별도 벡터 DB는 넣지 않는다. 자료 규모나 지연 시간이 실제로 문제가 되면 그때 검색 인덱스를 바꾼다. 질의 이미지는 사용자가 선택한 카탈로그 작품 이미지 또는 직접 입력한 파일을 허용하되, MVP는 질의 원본을 저장하지 않는 방식으로 둔다.

참고 양식의 객체 탐지/주시 추적, 벡터 DB, RAG, STT/TTS 단계 중 ArtBridge MVP에 필요한 이미지 임베딩·검색·작품 DB 흐름만 채택한다. 객체 탐지·스마트글라스·음성 안내는 입력이 작품 이미지로 이미 주어지므로 제외하고, RAG는 12절의 후속 단계로 남긴다.

### 6.3 모듈 명세와 코드 기능

각 코드 파일과 함수는 아래 책임만 가진다. 검색 결과의 이미지 유사도 점수와 메타데이터 비교를 분리해, 메타데이터가 임의의 가중치로 추천 순위를 바꾸지 않게 한다.

| 모듈 | 코드 / 함수 | 기능과 입력·출력 |
| --- | --- | --- |
| 카탈로그·권리 검증 | `src/catalog.py` — `load_catalog(path)` | `metadata.csv`와 같은 디렉터리의 `license_log.csv`를 읽어 작품별 권리 기록을 연결한다. 파일 누락·필수 열 누락을 명확한 오류로 알린다. |
| 카탈로그·권리 검증 | `src/catalog.py` — `validate_catalog(rows)` | 필수 `artwork_id`, `region`, 작품 페이지 URL, 이미지 경로를 검사하고 중복 ID·잘못된 권역·존재하지 않는 이미지 경로를 보고한다. 누락된 학술 정보는 임의로 채우지 않고 결측으로 둔다. |
| 카탈로그·권리 검증 | `src/catalog.py` — `approved_rows(rows, purpose)` | `rights_status`, 승인자, 용도, 필수 권리 필드를 확인해 해당 용도로 승인된 레코드만 반환한다. 파일 존재 여부는 보지 않는다. |
| 카탈로그·권리 검증 | `src/catalog.py` — `usable_image_rows(rows, purpose)` | `approved_rows` 결과 중 로컬 이미지 파일이 있고 기록된 `image_sha256`과 일치하는 레코드만 반환한다. 불명확·금지·허가 미확인 이미지는 임베딩 대상에서 제외한다. |
| 이미지 복원 | `src/fetch_images.py` — `fetch_catalog_images(rows, purpose)` | 승인된 레코드만 `image_source_url`에서 다시 받는다. 내려받은 파일의 해시가 기록과 다르면 저장하지 않고 `hash_mismatch`로 보고하며, 실패 건을 숨기지 않는다. |
| 이미지 임베딩 | `src/embed.py` — `load_image(path)` | 이미지 파일을 열고 손상 파일·지원하지 않는 형식을 오류로 분리한다. 색상 모드 변환과 모델 입력 전처리는 선택된 모델의 공식 processor에 맡긴다. |
| 이미지 임베딩 | `src/embed.py` — `embed_image(image, model, processor)` | 단일 이미지에서 모델 임베딩 벡터를 계산한다. 입력은 이미지와 고정된 모델/processor, 출력은 1차원 벡터다. |
| 이미지 임베딩 | `src/embed.py` — `embed_catalog(rows, model_id)` | 권리 사용이 허용된 카탈로그 이미지 전체를 같은 설정으로 벡터화하고, 각 벡터의 행이 어떤 `artwork_id`인지 함께 보존한다. 처리 실패 레코드는 이유와 함께 남긴다. |
| 이미지 임베딩 | `src/embed.py` — `save_embeddings(vectors, artwork_ids, model_id, manifest, output_path)` | 벡터와 ID 대응표, 모델명/체크포인트/전처리/데이터 버전/생성 시각을 지정 경로에 저장해 재현 가능한 임베딩 산출물을 만든다. |
| 유사도 검색 | `src/search.py` — `normalize_vectors(vectors)` | 벡터를 L2 정규화한다. 0 벡터나 NaN/무한 값은 점수 계산 전에 오류로 거른다. |
| 유사도 검색 | `src/search.py` — `cosine_top_k(query_vector, gallery_vectors, artwork_ids, k)` | 정규화 벡터의 행렬 곱으로 코사인 유사도를 계산하고 점수 내림차순 결과를 반환한다. 작은 카탈로그용 완전탐색 함수다. |
| 유사도 검색 | `src/search.py` — `recommend_cross_region(query_image, query_artwork, gallery, model, k=5, region_filter=None)` | 입력 작품이 한국 권역인지 확인하고, 카탈로그 이미지 또는 업로드 이미지를 임베딩한다. 후보는 해외 권역으로 제한하며 같은 `artwork_id`/`split_group_id`는 제외한다. 전체 Top-5와 선택적 권역별 Top-5를 점수·ID와 함께 반환한다. |
| 유사도 검색 | `src/search.py` — `search_saved_embeddings`, `search_uploaded_image` | 저장된 모델별 벡터와 카탈로그의 ID·이미지 해시를 확인한 뒤 카탈로그 또는 임시 입력 이미지의 해외 Top-k를 계산한다. |
| 메타데이터 비교 | `src/compare_metadata.py` — `compare_metadata(query_record, candidate_record, fields)` | 시대, 재질, 도상, 자세, 소장처 등의 질의/후보 값을 나란히 정리한다. 값이 없거나 기관 표현이 다르면 “미기재/표기 상이”로 표시하며 유사도 점수를 계산하지 않는다. |
| 평가·누수 점검 | `src/evaluate.py` — `precision_at_k(results, judgments, k=5)` | 사람이 관련 있다고 판정한 후보 비율을 질의별·전체 평균으로 계산한다. |
| 평가·누수 점검 | `src/evaluate.py` — `recall_at_k(results, judgments, k=5)` | 사전에 관련 후보로 표시한 전체 항목 중 상위 k개가 회수한 비율을 계산한다. 관련성 판정이 불완전한 경우 지표와 함께 제한을 기록한다. |
| 평가·누수 점검 | `src/evaluate.py` — `ndcg_at_k(results, graded_judgments, k=5)` | 0~2 등급 관련성 라벨이 있을 때 순위 상단의 관련 결과에 더 큰 비중을 주어 계산한다. |
| 평가·누수 점검 | `src/evaluate.py` — `check_query_gallery_leakage(queries, gallery, manifest)` | 동일 작품 ID·그룹 ID·이미지 해시가 질의와 갤러리에 함께 들어간 누수 사례를 찾아 목록으로 반환한다. |
| 데모 UI | `app.py` — `get_query_image(rows, input_mode)` | 사용자가 카탈로그의 한국 작품을 선택하거나 이미지 파일 또는 URL을 입력하게 한다. 질의 이미지는 파일로 저장하지 않는다. |
| 데모 UI | `app.py` — `run_recommendation(query, model_name, region, image=None, image_hash=None)` | 카탈로그/임베딩을 불러오고 검색·메타데이터 비교 모듈을 호출해 표시용 결과를 조합한다. 직접 입력은 사용자가 한국 작품 이미지를 지정한다. |
| 데모 UI | `app.py` — `render_results(results)` | Top-5 작품명·권역·모델 내 상대 코사인 점수·비교 메타데이터·공식 작품 페이지·이미지 크레딧을 카드로 표시한다. 점수를 역사적 영향이나 관계의 확률처럼 표현하지 않는다. |

권리 검증은 다운로드/사용 권한을 자동 판정하는 법률 엔진이 아니다. `usable_image_rows`는 사람이 `license_log.csv`에 입력하고 확인한 상태를 강제하는 게이트다. 새로운 용도(공개 웹 시연, 출판, 상업화)를 추가할 때는 용도에 맞는 허용 상태를 다시 확인한다.

## 9. 평가 지표와 데이터 누수 방지

| 측정 | 정의 및 사용 |
| --- | --- |
| Precision@5 | Top-5 가운데 사람 평가에서 관련(예: 형상·도상·자세 비교에 의미 있음)으로 표시한 비율의 평균. |
| Recall@5 | 평가 질의에 대해 미리 지정한 관련 후보 중 Top-5가 찾아낸 비율. 관련 후보를 완전히 판단할 수 없는 경우 제한을 함께 적는다. |
| nDCG@5 | 관련성 등급(예: 0~2)을 사용해 상위 순위에 더 높은 보상을 주는 순위 지표. 표본이 작으므로 정성 분석과 함께 해석한다. |
| 권역 분포 | Top-5 국가/권역 분포를 보고 특정 권역의 데이터 수가 많아서 결과를 점유하는지 점검한다. |
| 메타데이터 완성도 | 필수 필드 채움률, 권리 확인률, 출처 연결률, 이미지 사용 가능 비율을 각각 보고한다. |
| 사람 평가 일치 | 가능하면 두 차례 평가하거나 평가자 2인이 일부 결과를 중복 검토해 기준 해석 차이를 기록한다. |

### 9.1 데이터 누수 방지 규칙

- 동일 작품의 다른 각도, 같은 사진의 리사이즈/크롭, 중복 소장품 레코드는 artwork_id와 별도 split_group_id로 연결한다. 같은 작품 그룹을 질의와 후보 평가에 동시에 두지 않는다.

- 쿼리 이미지는 평가용으로 따로 고정한다. 검색 대상 갤러리에는 그 쿼리의 동일 원본 이미지나 near-duplicate를 포함하지 않는다.

- 같은 조각의 다른 각도를 허용할 실사용 시나리오를 평가하려면, 그것을 별도 “동일 객체 재식별” 과제로 분리하고 국가 간 유사 작품 추천 지표와 섞지 않는다.

- 평가 라벨을 본 뒤 임베딩 모델, 필터, 가중치를 반복 조정하면 평가셋에 과적합할 수 있다. 평가용 질의를 고정하고 탐색 세트와 최종 확인 세트를 구분한다.

- 수집 데이터, 이미지 파일 해시, 전처리, 모델/체크포인트, 평가 프로토콜을 버전으로 남긴다. 결과 비교는 같은 버전끼리 한다.

## 12. 향후 RAG 설명 기능의 준비 조건

RAG 설명은 MVP 이후 별도 단계로 둔다. 단순히 검색 결과를 생성형 모델에 넣는 방식으로 역사적 관계를 서술하지 않는다. 각 설명 문장은 출처 문단/페이지와 연결하고, 1차 자료의 주장과 시스템의 해석을 구분하며, 근거가 부족할 때는 비교를 유보해야 한다.

- 검색 코퍼스: 박물관 작품 상세 설명, 공개 전시 해설, 학술 출판물 중 이용 조건을 확인한 자료. 작품 레코드와 문단 단위 source_id를 유지한다.

- 응답 계약: 비교 항목별 주장, 근거 인용, 출처 URL, 불확실성 문구를 구조화한다. 인용 대상에 실제로 없는 주장은 출력하지 않는다.

- 평가: 출처 정확도, 주장-근거 일치, 잘못된 역사 관계 생성률을 사람 검토로 평가한다. 이미지 유사도 점수는 RAG 설명의 사실 근거로 쓰지 않는다.

## 부록 A. AI 도슨트 자료와의 관계

이 계획은 AI 도슨트 프로젝트의 작품 ID 연결, 공식 출처 기록, 이미지 권리 확인, 임베딩 기반 이미지 비교라는 기술 배경을 참고한다. 하지만 ArtBridge는 팀 과제/박물관 운영 시스템이 아니라 개인 프로젝트이며, 스마트글라스 입력·관람 로그·대화형 해설·운영 대시보드는 범위에 포함하지 않는다. 기존 자료 폴더의 `sources/`는 읽기 전용 참조 자료로 유지한다.
