# ArtBridge 모듈별 작업 관리

이 문서는 계획서의 6주 MVP를 작업 가능한 모듈로 나누고 진행 상태를 기록하는 기준표다. 세부 목적·데이터 권리 규칙·함수 계약은 [프로젝트 계획서](ArtBridge_프로젝트_계획서.md)와 [`AGENTS.md`](AGENTS.md)를 따른다.

## 상태 기준

| 상태 | 의미 |
| --- | --- |
| 미착수 | 파일·코드·검증 산출물이 아직 없다. |
| 진행 중 | 모듈 산출물을 만들고 있으며 완료 기준 일부가 남았다. |
| 검토 중 | 구현이 끝났고 아래 완료 기준을 확인하는 중이다. |
| 완료 | 산출물과 모듈 완료 기준을 확인했고, 상위 모듈과 연결했다. |
| 보류 | MVP 범위 밖이거나 선행 조건이 없어 의도적으로 멈춰 있다. 사유를 기록한다. |

## 의존 관계

```text
M0 기반·규약
  └── M1 작품·권리 데이터
       ├── M2 임베딩 ── M3 해외 Top-5 검색 ──┬── M5 평가
       │                                     └── M6 로컬 데모
       └── M4 메타데이터 비교 ───────────────┘

M7 RAG 설명은 MVP 완료 후 별도 범위로 검토
```

M4는 M2와 병렬로 진행할 수 있다. M5는 최종 평가 질의와 relevance judgment가 준비된 뒤 실행한다. 작은 데이터셋에서는 NumPy 기반 완전탐색을 사용하며, 성능 병목이 측정되기 전까지 별도 벡터 DB를 도입하지 않는다.

### M1 작품 수집·출처·이미지 권리

현재 진행 메모: Met, e뮤지엄, ColBase, Smithsonian API 수집기가 있으며 기관별 후보 CSV에 각각 30점이 있다. 원본 후보는 보존하고, 권역과 개별 이미지의 이용 근거를 연결할 수 있는 기존 후보 40점과 국립중앙박물관 한국 작품 5점을 `data/metadata.csv`, `data/license_log.csv`, `data/images/`에 연결했다. 실제 구성은 한국 5점·중국 21점·일본 10점·인도/간다라 9점이며, 기존 후보 중 미포함 사유는 `data/import_report.csv`에 기록했다. 권역별 파일럿 동결과 미확인 후보 검토가 남아 M1은 미완료다.

작품별 검토 근거는 `data/review_log.csv`에 기록한다. Met 후보 10점의 작품 페이지와 권리 표기를 검토했고, 인도/간다라로 분류한 9점은 API의 원본 이미지 URL과 Public Domain 표기를 대조해 카탈로그에 포함했다. MET_38230은 기관의 권역 표기와 설명문이 달라 원산지 분류를 보류했다. 나머지 후보의 작품별 검토가 필요하다.

네 후보 CSV의 120개 행을 `data/candidate_screening.csv`에 1차 분류했다. 분류는 CSV에 있는 기관 표기와 작품 유형을 근거로 한 후보 구분이며, 원산지와 이미지 권리의 개별 확인을 대신하지 않는다.

e뮤지엄 후보 30점은 `src/collect/link_emuseum_pages.py`로 작품별 e뮤지엄 상세 페이지에 연결해 `data/emuseum_page_links.csv`에 기록했다. 30점 모두 페이지의 명칭·소장품번호가 API 레코드와 일치하고 공공누리 제1유형(출처표시) 표기가 있다. 페이지 국적 표기는 한국 14점·중국 3점·아시아-기타 1점·표기 없음 12점이며, 다수가 불상 편·조각이다. 권역 분류, 이미지 파일 대조, `rights_status` 승인은 아직 하지 않았다.

Smithsonian 중국 작품 2점은 기관 전시의 지역 표기와 API의 개별 이미지 CC0 표기를 확인했다. ColBase 작품 5점은 기관의 원산지 근거, 이미지 URL, 출처표시 이용 조건을 연결했다. 개별 검토는 `data/review_log.csv`, 사용 상태는 `data/license_log.csv`에 기록한다.

- [ ] 한국·중국·일본·인도/간다라 후보를 5점씩 찾아 파일럿 후보 20점을 기록한다.
- [ ] 후보 전부에 개별 작품 페이지 URL과 메타데이터 확인일이 있다.
- [ ] 이미지별 권리 상태, 정확한 이용 조건, 권리 출처 링크, 확인일, 크레딧을 기록한다.
- [ ] 권리 사용이 확인되지 않은 이미지는 저장·임베딩하지 않는다.
- [ ] 파일럿 목표는 카탈로그 20점이며, 권리 확인 이미지 15점 미달 시 실제 수와 사유를 보고한다.
- [ ] 각 이미지에 `artwork_id`, 파일 경로, 해시와 선택 가능한 경우 `image_view_id`가 연결된다.

### M2 이미지 임베딩

`src/catalog.py`의 권리 기록·이미지 해시 게이트와 `src/embed.py`를 구현했다. 승인된 작품 45점에 대해 DINOv2와 CLIP을 실행해 `embeddings/dinov2.npz`, `embeddings/clip.npz`를 생성했다. 데이터 버전은 `catalog-733d356e41c7`이며 각 파일에 모델 리비전·전처리·라이브러리 버전·이미지 해시를 기록했다. 권역별 데이터 및 M1 파일럿은 아직 미완료다.

- [ ] 허용된 카탈로그 이미지만 같은 전처리 설정으로 배치 임베딩한다.
- [ ] DINOv2와 CLIP 결과를 각각 저장하고 벡터 행과 `artwork_id` 대응이 보존된다.
- [ ] 모델 체크포인트, 전처리, 라이브러리 버전, 임베딩 차원, 데이터 버전이 manifest에 기록된다.
- [ ] 손상 이미지와 실패 건을 식별할 수 있고 전체 배치가 조용히 누락되지 않는다.

### M3 해외 작품 유사도 검색

한국 카탈로그 작품을 사용한 두 모델의 전체 Top-5와 권역 필터를 실행했다. 업로드 이미지도 동일 모델 리비전으로 임베딩해 기존 갤러리와 검색하며, 동일 ID·그룹·이미지 해시는 제외한다. 추가 데이터와 오류 경로 확인이 남았다.

- [ ] 카탈로그 한국 작품 선택과 이미지 입력이 같은 검색 경로로 연결된다.
- [ ] 후보 갤러리는 해외 권역으로만 제한되고 기본 반환 개수는 5다.
- [ ] 코사인 유사도 기준 내림차순으로 반환하며 같은 객체/그룹을 제외한다.
- [ ] 빈 후보, 잘못된 이미지, 0/비정상 벡터, 한국 작품이 아닌 질의를 식별해서 처리한다.
- [ ] 검색 결과에 작품 ID, 권역, 원점수, 이미지/메타데이터 출처가 연결된다.

### M4 메타데이터 비교

시대·재질·도상·자세를 원문과 함께 병렬 비교한다. 정규화 값이 없는 항목은 원문 표기 차이 또는 결측으로 표시하며 검색 순위에 반영하지 않는다.

- [ ] 시대, 재질, 도상, 자세 중 확인 가능한 값만 쌍으로 표시한다.
- [ ] 원문 값과 정규화 값을 구별하고, 누락·불일치·불확실성을 표시한다.
- [ ] 비교 모듈은 이미지 검색 순위를 변경하지 않는다.

### M5 평가·누수 점검

- [ ] 한국 질의 10점 이상과 사람이 검토한 관련성 판정이 고정되어 있다.
- [ ] Precision@5, Recall@5, nDCG@5, 권역별 결과 수와 평가 표본 수를 기록한다.
- [ ] 같은 작품, 다른 각도, 복제 레코드, 같은 원본 이미지의 변형이 query/gallery에 동시에 들어가지 않는다.
- [ ] 대표 오류 사례와 평가 한계를 기록하고, 작은 평가셋의 점수를 일반화 성능으로 과장하지 않는다.

### M6 로컬 데모

`src/fetch_images.py`로 승인 이미지를 기록된 URL에서 다시 받고 SHA-256이 일치하는 파일만 저장한다. `uv run streamlit run app.py`로 카탈로그 선택 또는 파일·URL 이미지 입력, 모델·권역 선택 및 결과 카드를 실행한다. 질의 이미지는 파일로 저장하지 않는다. 깨끗한 환경에서의 전체 재현과 평가가 남았다.

- [ ] 작품 선택 또는 임시 이미지 입력으로 추천 흐름을 시작할 수 있다.
- [ ] 결과 카드에 Top-5, 권역, 비교 메타데이터, 공식 작품 페이지와 이미지 크레딧이 보인다.
- [ ] 업로드 질의 이미지를 기본적으로 영구 저장하지 않는다.
- [ ] 모델 점수를 역사적 영향이나 관계의 확률처럼 제시하지 않는다.
- [ ] 실행 방법과 데이터/모델 버전이 README에 있다.

### M7 근거 기반 RAG 설명 — 보류

- MVP에서는 구현하지 않는다. 후속 착수 전 자료 이용 권리, source_id 체계, 주장-근거 일치 평가와 불확실성 표현을 별도 계획으로 승인한다.

## 작업 갱신 규칙

1. 작업은 선행 모듈이 완료되었거나 독립 작업으로 가능한 모듈부터 선택한다.
2. 모듈 작업을 시작하면 상태를 `진행 중`으로 바꾸고, 무엇을 바꾸는지 산출물 경로와 함께 기록한다.
3. 완료 기준을 충족하면 관련 코드·자료를 확인한 뒤 상태를 `검토 중`, 최종 확인 후 `완료`로 바꾼다. 파일이 생겼다는 사실만으로 완료 처리하지 않는다.
4. 막히면 모듈 상태를 `보류`로 두고, 원인과 다음에 필요한 입력을 기록한다. 해결 가능한 다른 모듈은 계속 진행한다.
5. 모듈 인터페이스나 계획이 달라지면 먼저 이 보드와 `ArtBridge_프로젝트_계획서.md`의 모듈 명세를 함께 맞춘다.
